# 예상 질문 / 답변

## Q. 왜 외부 AI를 쓰지 않고 사내 챗봇을 만드나요?
외부 AI가 모르는 내부 규정·업무 문서가 있고, 사내 문서를 무분별하게 외부에 전달하기 어렵기 때문입니다. 프로젝트에서는 권한 기반 RAG 구조로 내부 지식을 활용합니다.

## Q. 초기 해결률 30%와 3개월 45.1%는 실제 기업 수치인가요?
아닙니다. 프로젝트 시뮬레이션 값입니다. 특정 기업의 실제 효과나 인과관계를 주장하지 않습니다.

## Q. 동료 재문의는 어떻게 알 수 있나요?
챗봇 답변 후 해결 여부와 후속 행동을 사용자에게 선택받아 기록한다고 가정합니다.

## Q. 챗봇 사용량이 증가하면 성공인가요?
아닙니다. 해결률, 재질문, 동료 재문의, FAQ/RAG/LLM 비율과 시스템 오류를 함께 봅니다.

## Q. FAQ는 자동 등록하나요?
아닙니다. 반복 질문 후보를 탐지한 뒤 관리자가 검토하고 승인합니다.

## Q. LLM 호출률을 왜 줄이나요?
무조건 줄이는 것이 목표가 아닙니다. FAQ나 사내 지식으로 충분한 질문에 불필요하게 LLM을 쓰지 않는 것이 목표입니다.

## Q. RAG도 LLM을 호출하는데 왜 별도로 보나요?
RAG는 회사 문서를 근거로 답변하는 처리 경로이고, Direct LLM은 별도 내부 문서 근거 없이 복합 질문을 처리하는 경로입니다. 자원과 품질 원인을 구분하기 위해 따로 봅니다.

## Q. 특정 직원 Token이 많으면 과다사용인가요?
바로 그렇게 판단하지 않습니다. 요청 수, Context 크기, RAG 검색량, Retry, 오류를 먼저 확인합니다.

## Q. CPU/Memory가 낮아지면 챗봇 효율이 좋아진 건가요?
아닙니다. CPU/Memory는 서비스 장애 원인을 찾기 위한 시스템 지표입니다.
